# Translation Log

| Term | Plain meaning | Problem it solves | Where it shows up at clients |
|---|---|---|---|
| Repo | A project folder with tracked history | Keeps every version of the work in one place so nothing gets lost | Every client product lives in one, like DefraDB and the Second Moment website |
| Commit | A saved snapshot with a note about what changed | Shows who changed what and why, so mistakes can be traced and undone | The commit history shows how active a client's project is |
| README | The front page of a repo that explains what it is | Tells a newcomer what the project does and how to start | Often the first thing a developer reads when they're deciding whether to try a client's product |
| Issue | A public note describing a problem or a change someone wants | Makes work visible and open for discussion before anyone starts | Where users report bugs and ask for features, so it's a signal of real demand |
| Branch | A separate copy where changes are made without touching the main version | Lets people experiment without breaking what everyone relies on | Every pull request at DefraDB comes from a branch |
| Main | The official, working version of the project | Gives everyone one trusted version to build from | What users actually download and run |
| Pull request | A request to add my changes to the main version | Lets someone check a change before it goes live | DefraDB reviews them within a few hours |
| Merge | Accepting a pull request so its changes join main | Makes an approved change official | A merged pull request from an outside contributor is a sign of a healthy community |
| LGTM | Short for "looks good to me," a reviewer's approval | Gives a quick, clear signal that a change is ready | Common in reviewer comments on client pull requests |
| Nit | A small, optional suggestion, like a typo or formatting fix | Flags minor issues without blocking the change | Reviewers use it to stay helpful without sounding harsh to contributors |
